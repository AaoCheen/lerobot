# 01｜先跑通仿真工作流

目标不是立刻改模型，而是先知道一条完整命令能否运行。

## 1. 安装基础仓库

在仓库根目录：

~~~bash
cd /home/ca/big_space/my_project/Embodied_Inteligence/my_forks/lerobot
uv sync --locked
~~~

不同 benchmark 可能还需要额外依赖。不要一开始把所有 benchmark 装进一个环境，先选择一个主线。

## 2. 推荐第一条主线：LIBERO

LIBERO 依赖 MuJoCo，当前学习阶段只做仿真：

~~~bash
export MUJOCO_GL=egl
~~~

安装对应 extra：

~~~bash
uv sync --locked --extra libero
~~~

实际依赖和版本以 [docs/source/libero.mdx](../source/libero.mdx) 为准。

## 3. 先做最小评测

准备一个已经兼容 LIBERO 的 checkpoint 后：

~~~bash
lerobot-eval \
  --policy.path=<模型checkpoint> \
  --env.type=libero \
  --env.task=libero_spatial \
  --eval.n_episodes=1 \
  --eval.batch_size=1
~~~

先只跑一个 task、一个 episode。确认：

- 环境可以启动；
- policy 可以加载；
- observation key 能对齐；
- action 可以送入环境；
- 日志能记录 success/failure。

## 4. 再跑标准评测

~~~bash
lerobot-eval \
  --policy.path=<模型checkpoint> \
  --env.type=libero \
  --env.task=libero_spatial,libero_object,libero_goal,libero_10 \
  --eval.n_episodes=10 \
  --eval.batch_size=1
~~~

正式结果应固定：

- LeRobot 代码 commit；
- policy checkpoint revision；
- benchmark 版本；
- 数据集 revision；
- 随机种子；
- 每个 task 的 episodes；
- control mode 和 action steps。

## 5. 执行失败时先看哪一层

~~~text
环境启动失败       → 依赖、MuJoCo、渲染后端
checkpoint加载失败 → policy 类型、模型依赖、Hub 权限
key/shape错误      → dataset、rename_map、processor
动作执行异常       → action space、控制模式、归一化
结果很低           → 先确认 baseline 和评测协议，再怀疑模型
~~~

## 6. 当前不做什么

本阶段先不做：

- 真实机器人连接；
- lerobot-record 采集真机数据；
- 电机标定；
- 相机设备调试；
- 同时运行多个不同 simulator；
- 一开始就改 policy 结构。
