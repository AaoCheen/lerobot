# 07｜论文实验路线

## 1. 先选择一个清晰问题

好的第一版问题应当能写成：

~~~text
在固定 benchmark、固定数据和固定 policy 下，
某个改动是否改善某个可测指标？
~~~

例如：

- temporal observation/action chunk 是否改善 LIBERO-plus OOD；
- 一个 processor/harness 是否改善任务一致性；
- policy tool 调用策略是否改善长时序任务；
- 某种训练采样或 augmentation 是否改善 camera/layout OOD；
- 多个 task 的训练混合方式是否改善跨任务泛化。

## 2. 建议的实验阶段

### Phase 0：复现原始 baseline

~~~text
固定模型、数据集、benchmark、seed
跑最小评测
再跑正式评测
~~~

### Phase 1：只做一个改动

~~~text
baseline
vs
baseline + 你的改动
~~~

同时保留相同：

- 训练步数；
- batch size；
- 数据 revision；
- checkpoint 初始化；
- eval episodes；
- 评测 seed。

### Phase 2：做消融

至少包含：

~~~text
完整方法
去掉关键模块
替换为简单策略
不同超参数
~~~

### Phase 3：外部验证

主实验可以使用 LIBERO/LIBERO-plus，之后再增加 RoboTwin、RoboMME 或 IsaacLab Arena 中的一个外部 benchmark。跨 simulator 结果单独报告。

## 3. 论文中必须记录的证据

~~~text
代码 commit
运行命令
依赖环境
GPU
Python
LeRobot commit
benchmark commit
数据集 revision
policy checkpoint revision
训练 steps
seed
每个 task 的 success
均值和方差
失败案例
~~~

## 4. 结果表的最小形式

| Method | Train data | ID success | OOD success | Seed mean ± std |
|---|---|---:|---:|---:|
| baseline | lerobot/libero | | | |
| ours | lerobot/libero | | | |

如果有多个 OOD 维度，再拆成：

~~~text
layout / camera / language / lighting / texture / noise
~~~

## 5. 不能直接当作论文结论的东西

~~~text
训练 loss 更低
→ 不等于 benchmark success 更高

一个 task 成功
→ 不等于泛化能力更强

多个 benchmark 的平均值更高
→ 不一定公平，可能是动作空间和难度不同

更多训练数据
→ 不等于方法改动有效
~~~

## 6. 你当前最稳的主线

~~~text
SmolVLA 或 Pi05
+ lerobot/libero
+ LIBERO ID
+ LIBERO-plus OOD
+ 一个明确的 processor / temporal / harness 改动
+ 完整 ablation
~~~

先把这一条线跑通，再考虑跨 simulator 或更大的 VLA。
