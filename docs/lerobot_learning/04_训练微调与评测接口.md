# 04｜训练、微调与评测接口

## 1. 训练入口：lerobot-train

训练入口在：

~~~text
src/lerobot/scripts/lerobot_train.py
~~~

常见参数分为：

~~~text
--dataset.*   数据集、episode、视频、streaming
--policy.*    policy 类型、checkpoint、dtype、冻结策略
--batch_size  batch大小
--steps       训练步数
--output_dir  输出目录
--seed        随机种子
--wandb.*     实验记录
--eval.*      训练期间的评测
~~~

查看完整参数：

~~~bash
lerobot-train --help
~~~

## 2. 从 checkpoint 微调

常见两种形式：

~~~text
--policy.path
加载一个已保存的 LeRobot checkpoint 和它的配置。

--policy.type + --policy.pretrained_path
指定 policy 类型，再从预训练权重初始化。
~~~

它们不是所有模型都可以互换。优先使用目标 policy 文档中的命令。

## 3. 训练期间的评测

有些训练配置可以定期调用环境评测：

~~~text
env_eval_freq
eval_steps
eval.batch_size
eval.n_episodes
~~~

初学时可先关闭训练中评测，确认离线训练能跑通，再打开评测。否则训练、环境和模型问题会同时出现。

## 4. 评测入口：lerobot-eval

~~~bash
lerobot-eval \
  --policy.path=<checkpoint> \
  --env.type=libero \
  --env.task=libero_spatial \
  --eval.n_episodes=1
~~~

评测循环大致是：

~~~text
reset
→ observation
→ policy preprocessing
→ select_action
→ action postprocessing
→ env.step
→ success / failure
~~~

## 5. policy、processor、environment 的职责

~~~text
environment
提供 observation、接收 action、判断 success。

processor
把环境 observation 变成 policy 输入，
把 policy 输出变成环境 action。

policy
只负责根据输入预测动作和训练 loss。
~~~

这个分工对改代码很重要：如果只是字段重命名或归一化，不要直接改 policy；如果是新的 benchmark 观测接口，优先写 processor。

## 6. 输出要保存什么

论文实验至少保留：

~~~text
代码 commit
数据集 repo_id 和 revision
checkpoint
policy 配置
benchmark 版本
运行命令
随机种子
每个 task 的 success
完整日志
~~~

## 7. Harness 的位置

如果把 VLA policy 当作一个 tool，推荐先包装标准接口：

~~~text
输入：task + observation
调用：policy.select_action
输出：action chunk
执行：benchmark environment
返回：observation + success + trace
~~~

不要一开始重写 lerobot-eval。先做一个外部 Python harness，确认输入输出和标准评测结果一致，再决定是否把它集成进 processor、rollout 或 env wrapper。
