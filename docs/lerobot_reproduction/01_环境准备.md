# 01：LIBERO-Plus VLA 环境准备

当前只复现 **LIBERO-Plus**，只做 VLA。如果 vanilla LIBERO 与 LIBERO-Plus 冲突，一律保留 LIBERO-Plus；不再为 vanilla LIBERO 建第二套环境。

本阶段的主线：

- 训练数据：`lerobot/libero_plus`
- 主模型起点：`lerobot/pi05_libero_base`
- 可选轻量基线：`lerobot/smolvla_base`
- 环境与评测入口：`--env.type=libero_plus`

`lerobot/pi05_libero_base` 是 Pi0.5 的 LIBERO 起始权重，不是已练好的 LIBERO-Plus 最终 checkpoint。我们将用它在 `lerobot/libero_plus` 上训练，并把训练后 checkpoint 与这个起点权重在相同 LIBERO-Plus 协议下对比。

## 1. 确认仓库与分支

```bash
cd /home/ca/big_space/my_project/Embodied_Inteligence/my_forks/lerobot
git branch --show-current
git status --short --branch
```

当前笔记分支应为 `dataset-notes`。下面命令均默认在该仓库根目录执行。

## 2. 检查系统

LIBERO-Plus 当前只支持 Linux，Pi0.5 训练和 MuJoCo EGL 评测需要 NVIDIA GPU。

```bash
uname -a
uv --version
nvidia-smi
df -h . "$HOME/.cache/huggingface"

sudo apt-get update
sudo apt-get install -y \
  unzip libexpat1 libfontconfig1-dev libmagickwand-dev
```

Plus assets 压缩包约 6.4 GB，还需为解压文件、数据集、Pi0.5 权重和训练 checkpoint 预留额外空间。

## 3. 创建唯一的 LIBERO-Plus 环境

不复用仓库中可能已有的 `.venv`，也不创建 vanilla LIBERO 环境：

```bash
export LIBERO_PLUS_ENV=.venv-libero-plus

UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv sync --locked \
  --extra evaluation \
  --extra libero \
  --extra pi \
  --extra smolvla
```

`--extra libero` 先补齐 LeRobot 数据和 LIBERO 接口依赖；后面会卸载 `hf-libero`，让 `import libero` 只指向 LIBERO-Plus fork。

每次打开新终端，在仓库根目录设置：

```bash
export LIBERO_PLUS_ENV=.venv-libero-plus
export MUJOCO_GL=egl
export LIBERO_PLUS_ROOT="$PWD/third_party/LIBERO-plus/libero/libero"
export PYTHONPATH="$PWD/third_party/LIBERO-plus${PYTHONPATH:+:$PYTHONPATH}"
```

## 4. 安装 LIBERO-Plus fork

固定到当前 LeRobot canonical Dockerfile 使用的 commit：

```bash
mkdir -p third_party
git clone https://github.com/sylvestf/LIBERO-plus.git third_party/LIBERO-plus
git -C third_party/LIBERO-plus checkout 4976dc3
```

如果已经 clone，不要重复 clone，改为：

```bash
git -C third_party/LIBERO-plus fetch origin
git -C third_party/LIBERO-plus checkout 4976dc3
```

安装与 canonical Dockerfile 一致的运行时依赖：

```bash
UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv pip install \
  --python "$LIBERO_PLUS_ENV/bin/python" \
  "robosuite==1.4.1" "bddl==1.0.1" "easydict==1.13" \
  "mujoco==3.7.0" "matplotlib==3.10.8" "Wand==0.6.13" \
  "scikit-image==0.25.2" "gym==0.26.2"

UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv pip install \
  --python "$LIBERO_PLUS_ENV/bin/python" \
  --no-deps -e third_party/LIBERO-plus

UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv pip uninstall \
  --python "$LIBERO_PLUS_ENV/bin/python" hf-libero
```

LIBERO-Plus 与 vanilla LIBERO 共用 Python 包名 `libero`。卸载 `hf-libero` 是预期操作，不要把它重新装回来。Plus fork 必须通过前面的 `PYTHONPATH` 显式覆盖。

## 5. 下载并配置 Plus assets

```bash
UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv run --no-sync python -c \
  "from huggingface_hub import hf_hub_download; hf_hub_download(repo_id='Sylvest/LIBERO-plus', repo_type='dataset', filename='assets.zip', local_dir='third_party/LIBERO-plus-download')"

mkdir -p third_party/LIBERO-plus-extract
unzip -q third_party/LIBERO-plus-download/assets.zip \
  -d third_party/LIBERO-plus-extract
find third_party/LIBERO-plus-extract -type d -name assets
```

`find` 应只返回一个真正的 `assets` 目录。确认后，将该目录移到：

```text
third_party/LIBERO-plus/libero/libero/assets
```

然后写入 LIBERO-Plus 配置，避免首次 import 时进入交互式路径询问：

```bash
mkdir -p "$HOME/.libero"
LIBERO_PLUS_ROOT="$PWD/third_party/LIBERO-plus/libero/libero"

printf 'assets: %s/assets\nbddl_files: %s/bddl_files\ndatasets: %s/../datasets\ninit_states: %s/init_files\n' \
  "$LIBERO_PLUS_ROOT" "$LIBERO_PLUS_ROOT" \
  "$LIBERO_PLUS_ROOT" "$LIBERO_PLUS_ROOT" \
  > "$HOME/.libero/config.yaml"
```

assets 体积很大，不要提交到当前笔记分支。

## 6. 验证 Plus 已经覆盖 vanilla LIBERO

```bash
export MUJOCO_GL=egl
export LIBERO_PLUS_ROOT="$PWD/third_party/LIBERO-plus/libero/libero"
export PYTHONPATH="$PWD/third_party/LIBERO-plus${PYTHONPATH:+:$PYTHONPATH}"

UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv run --no-sync python - <<'PY'
import libero
import mujoco
import robosuite

print("libero =", libero.__file__)
print("mujoco =", mujoco.__version__)
print("robosuite =", robosuite.__version__)
assert "third_party/LIBERO-plus" in libero.__file__, libero.__file__
PY
```

`libero.__file__` 必须指向当前仓库下的 `third_party/LIBERO-plus`。如果指向 `site-packages/libero`，说明 vanilla `hf-libero` 仍在抢占 import，此时不要开始训练或评测。

## 7. 准备数据集和模型权重

Pi0.5 使用 gated 的 `google/paligemma-3b-pt-224` tokenizer。先在 Hugging Face 页面接受许可，再登录：

```bash
hf auth login
hf auth whoami
```

预下载数据集和主基线权重：

```bash
UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv run --no-sync python - <<'PY'
from huggingface_hub import snapshot_download

snapshot_download(repo_id="lerobot/libero_plus", repo_type="dataset")
snapshot_download(repo_id="lerobot/pi05_libero_base")
PY
```

如需轻量 VLA 基线，只补 SmolVLA：

```bash
UV_PROJECT_ENVIRONMENT="$LIBERO_PLUS_ENV" uv run --no-sync python -c \
  "from huggingface_hub import snapshot_download; snapshot_download(repo_id='lerobot/smolvla_base')"
```

不再加 XVLA、ACT、Diffusion Policy 或其他非必要基线。

## 8. 训练前的固定约定

后续 Pi0.5 训练命令至少固定：

```text
dataset.repo_id = lerobot/libero_plus
policy.type = pi05
policy.pretrained_path = lerobot/pi05_libero_base
env.type = libero_plus
policy.n_action_steps = 10
policy.empty_cameras = 1
normalization = MEAN_STD for ACTION and STATE
```

`n_action_steps=10` 和 `empty_cameras=1` 必须显式传入：`pretrained_path` 只加载权重，不会自动继承这两个配置值。

最终对比时，`lerobot/pi05_libero_base` 和自己训练的 checkpoint 必须使用完全相同的 LIBERO-Plus task suite、task IDs、episode 数、seed、control mode 和 hard-reset 设置，才能判断训练后 checkpoint 是否真正超过起始基线。
